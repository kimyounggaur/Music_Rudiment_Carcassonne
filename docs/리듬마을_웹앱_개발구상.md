## 2. 확정한 결정

| 항목 | 결정 |
|---|---|
| 1차 목표 | 핫시트(한 기기로 사람끼리) + 솔로(컴퓨터 상대·퍼즐) 먼저. 온라인·교실은 3단계 |
| 기준 화면 | 가로 태블릿. 세로 태블릿·휴대폰은 축소 배치로 대응 |
| 시각 스타일 | 기본은 '음악 마을' 테마(풀밭 타일·흙길·나무 테이블). 설정·메뉴에서 '카드' 테마(인쇄용 리마스터 카드 색)로 바꿀 수 있음 |
| 그림 원칙 | 카르카손 원작의 그림·디자인은 따라 하지 않은 독창적인 그림. 규칙·좌표·지휘자 자리는 두 테마가 같음 |
| 학습 모드(검산 퀴즈) | 기본 켜짐. 내가 닫은 마디는 점수를 주기 전에 "몇 박?"을 먼저 묻고, 답하면 풀이와 리듬 소리 |
| 덜 찬 마디 닫기 금지 | 옵션, 기본 켜짐 (8장 시뮬레이션 근거) |
| Lv2 박자표 | 숫자가 적힌 쪽부터 적용, 다음 박자표까지 마디줄을 건너 이어짐 (7장) — **확인 필요** |
| 쉼표 | 박자합에 더하고 점수는 1장당 1점 (설계서 그대로) |
| 박자표 타일의 지휘자 | 올릴 수 없음 (음표가 아닌 표지판) |
| Lv2 마디줄 | 심화 봉투를 넣으면 마디줄 +8개 (MVP 24 → 32, 완전판 40 → 48). 플레이테스트로 조정할 값 |
| 학습 퍼즐 | 게임과 같은 룰 엔진 위의 한 수 문제. 틀려 보고 고치는 연습이 목적이라 Lv0의 '틀린 마디 금지'는 퍼즐에서 끔 (5장) |
| 컴퓨터 실력 | 쉬움(막지 않음) · 보통(1수 평가) · 어려움(상대의 받아치기까지 2수 앞 읽기, 최대 1.2초) (6장) |

## 3. 구조

```
타일 데이터(카드 마스터 데이터 92장) ─┐
타일 그림(리마스터 SVG 스타일) ───────┤
                                      ▼
        룰 엔진 (TypeScript, 화면과 분리, 자동 테스트 24개)
                                      ▼
   게임 진행 관리 (차례 흐름 · 컴퓨터 · 정산 연출 · 퀴즈 · 튜토리얼 · 퍼즐)
                                      ▼
        화면 (React: 설정 · 보드 · 손패 · 점수판 · 시트 · 퍼즐 목록·풀이)
                                      ▼
  핫시트 · 솔로(컴퓨터 쉬움/보통/어려움) · 학습 퍼즐 · 온라인/교실(3단계)
```

엔진은 "현재 상태 + 행동 → 다음 상태"만 계산합니다. 상태는 JSON 그대로 저장되는 객체라 저장·이어하기·되돌리기·리플레이가 같은 방식이고, 온라인은 나중에 "행동을 방에 보내기"만 붙이면 됩니다. 학습 퍼즐도 같은 엔진 상태를 써서, 게임 규칙과 퍼즐 채점이 어긋나지 않습니다.

### 코드 구성 (Vite + React 18 + TypeScript)

| 파일 | 역할 |
|---|---|
| `src/engine/engine.ts` | 규칙 전부: 타일 카탈로그(Lv2 포함), 변 맞추기, 마디 추적, 박자표 목표 계산, 지휘자·마디줄 합법성, 정산 |
| `src/engine/ai.ts` | 컴퓨터 3단계. 계산을 조금씩 나눠 할 수 있는 생성기 구조 |
| `src/engine/ai.worker.ts` | 컴퓨터 계산 전용 워커 (설치형 빌드) |
| `src/engine/engine.test.ts` | 엔진·컴퓨터 자동 테스트 18개 |
| `src/art/tiles.ts` | 카드 테마 타일·지휘자·마디줄 SVG (Lv2 기호 포함), 공통 기하 |
| `src/art/village.ts` | 음악 마을 테마 그림 (풀밭 타일, 흙길, 나무 차단목, 음악 정자, 나무 말, 나무 테이블 무늬) |
| `src/art/skin.ts` | 테마 고르기: 그림을 그리는 곳은 모두 이 모듈을 거침 |
| `src/game/controller.ts` | 게임 진행 관리: 차례 흐름, 컴퓨터 차례 연출, 정산·퀴즈, 저장·이어하기, 퍼즐 진행 |
| `src/game/puzzle.ts` | 학습 퍼즐: 문제 형식·검사·단원 문제 36개·무한 연습 생성기 |
| `src/game/puzzle.test.ts` | 퍼즐 자동 테스트 6개 (모든 문제가 풀리는지, 생성 문제 900개 검증) |
| `src/game/aiRunner.ts` | 컴퓨터 계산을 워커 또는 '시간 나눠 계산'으로 돌림 |
| `src/game/tutorial.ts` | 튜토리얼 단계 정의 |
| `src/game/audio.ts` | 완성 마디 리듬 재생 (쉼표는 소리 없이 박만, 여러 마디면 첫 박 강세) |
| `src/ui/*.tsx` | React 화면 |
| `scripts/ai-match.ts` | 컴퓨터끼리 맞붙여 실력 비교하는 도구 |

### 빌드 두 가지

| 명령 | 결과 | 쓰는 곳 |
|---|---|---|
| `npm run build:artifact` | HTML 한 파일 (React는 jsDelivr에서 불러옴, 약 160KB) | Claude 아티팩트 게시 |
| `npm run build:web` | 여러 파일 + 서비스워커 + 매니페스트 + 아이콘 + 컴퓨터 워커 | 내 주소에 올려 태블릿에 설치 (10장) |

룰 엔진 원본은 이 프로젝트의 `claude/리듬마을_룰엔진.ts`에도 저장해 두었습니다.

## 4. 설계서의 빈틈 → 앱에서 정한 규칙 해석

| 설계서에서 비어 있던 부분 | 앱의 처리 |
|---|---|
| 빈 칸을 향한 열린 끝에 마디줄 | 가능 (13장 샘플 플레이와 일치). 배경 변에는 불가 |
| 같은 이음새에 마디줄 두 번 | 불가 |
| 이미 정산된 마디 안에 마디줄 | 불가 |
| 음표가 하나도 없는 빈 마디 | 만들 수 없음 (쉼표만 있어도 가능) |
| 지휘자 자격 판정 시점 | 마디줄을 꽂기 전 기준 (②지휘자 → ③마디줄) |
| 타일만 놓아도 닫히는 마디 (양쪽 막대 사이 빈칸) | 바로 정산 |
| 리듬선이 고리 모양 | 마디줄 1개면 닫힘, 없으면 열린 마디 |
| 지휘대(통과) | 0박, 음표 장수에서 제외. 리듬선·지휘대 중 한 곳에 지휘자 |
| 놓을 곳이 없을 때 | 한 장 공개해 빼 두고 새로 뽑기 반복 |
| 게임 끝 시점 | 주머니와 모든 손패가 빈 차례가 끝날 때 |
| 동점 | 완성 마디 수 → 공동 우승 |
| Lv0 "4박일 때만 마디줄" | 마디줄·타일 모두 틀린 마디를 만드는 수는 불가 (퍼즐에서는 끔) |
| Lv2 "가장 가까운 위쪽 박자표" | 7장 규칙 |
| Lv2 박자표 타일을 놓아 마디가 닫히는 경우 | 박자표 타일도 마디줄처럼 마디를 닫음. 덜 찬 마디 금지가 켜져 있으면 덜 찬 마디를 닫는 자리에는 못 놓음 |

## 5. 학습 퍼즐 (2단계)

처음 화면의 '학습 퍼즐'에서 들어갑니다. 실제 게임 규칙 그대로 한 수씩 풀며 박자를 익힙니다.

### 문제 형식

| 형식 | 하는 일 | 익히는 것 |
|---|---|---|
| 박 세기 | 음표·쉼표·마디를 보고 몇 박인지 고르기 (풀기 전엔 타일의 박자 숫자를 숨김) | 음표값 읽기, 박 더하기 |
| 채우기 | 손패 3장 중 맞는 타일을 골라 놓고, 필요하면 마디줄로 닫기 | "3박 찼으니 1박 모자라 → 4분음표" (설계서의 학습 핵심) |
| 마디줄 긋기 | 이어진 리듬에 마디줄을 꽂아 목표 박 마디로 나누기 | 악보의 '마디줄 긋기', 박자표에 맞춰 마디 나누기 |

### 단원

| 장 | 주제 | 난이도 | 문제 수 |
|---|---|---|---|
| 1 | 1박 · 2박 · 4박 (4분·2분·온음표) | Lv0 | 10 (세기 4 · 채우기 4 · 긋기 2) |
| 2 | 3박 · 점2분음표 | Lv1 | 6 (세기 2 · 채우기 3 · 긋기 1) |
| 3 | 쉼표도 박을 세요 | Lv2 | 6 (세기 3 · 채우기 2 · 긋기 1) |
| 4 | 반 박 · 8분음표와 점4분음표 | Lv2 | 7 (세기 3 · 채우기 3 · 긋기 1) |
| 5 | 박자표 3/4 · 2/4 (중간에 박자가 바뀌는 문제 포함) | Lv2 | 7 (세기 1 · 채우기 4 · 긋기 2) |

### 진행과 피드백

- 목표 마디는 점선으로 둘러 보여 줍니다. 채우기는 타일을 놓은 뒤에 마디줄 자리가 나타납니다 (게임의 ①타일 → ③마디줄 순서와 같게).
- 마디가 닫히면(채우기) 또는 마디줄을 다 꽂으면(긋기) 저절로 채점합니다. 틀리면 "5박이에요. 목표 4박보다 1박 많아요." 처럼 무엇이 틀렸는지 말해 주고, 해당 칸을 빨간 점선으로 표시합니다. '되돌리기'·'처음부터'로 고칩니다.
- 힌트는 단계별로 1~2개. 두 번 틀리면(박 세기는 한 번) 다음 힌트가 저절로 보입니다.
- 정답이면 박 계산식(1 + 2 + 1 = 4박)과 함께 리듬을 들려줍니다. 여러 마디는 마디 첫 박에 강세.
- 별: 3개에서 틀린 횟수만큼, 그리고 직접 힌트를 봤으면 1개를 뺍니다 (최소 1개). 저절로 보인 힌트는 빼지 않습니다. 기기에 저장되고 목록에 단원별로 표시됩니다.
- 튜토리얼을 마치면 '학습 퍼즐'로 바로 갈 수 있습니다.

### 무한 연습

- Lv0 · Lv1 · Lv2 중 고르면 문제가 끝없이 새로 만들어집니다 (채우기 60% · 긋기 40%, Lv2는 35%가 3/4·2/4 줄).
- 한 번에 맞힌 문제만 '연속 정답'으로 이어지고, 난이도별 최고 기록을 저장합니다.
- 만들어지는 문제는 모두 자동 검증: 채우기는 정답이 있고 틀릴 선택지도 있으며, 긋기는 정답이 하나뿐이고, 줄 길이는 시작 타일 포함 9칸 이하.

## 6. 컴퓨터 실력 3단계와 속도 (2단계)

| 단계 | 방식 |
|---|---|
| 쉬움 | 자기 마디만 채움. 상대 마디를 일부러 넘치게 막지 않음 (어린이용) |
| 보통 | 손패 × 모든 자리·회전 × 지휘자·마디줄 선택을 시뮬레이션해 1수 평가 |
| 어려움 | 보통의 상위 6수에 대해, 다음 사람이 가장 좋게 받아치는 수까지 둬 보고 다시 평가 (2수 앞 읽기). 상대 손패는 보지 않고, 아직 안 나온 타일을 섞은 '가능한 세계' 4개로 평균 |

**실력 검증** (컴퓨터끼리, 자리 번갈아):

| 조건 | 어려움 승 | 보통 승 | 무승부 |
|---|---|---|---|
| 2인 MVP Lv1, 100판 | 57% | 34% | 9% |
| 3인 MVP Lv1, 60판 | 53% | 43% | 3% |
| 2인 MVP Lv2, 60판 | 55% | 42% | 3% |

시도했다가 버린 방법: "내 손패로 남은 박을 채울 수 있으면 내 마디 가치를 높게 본다"는 단순 보정은 오히려 약했습니다(보통에게 29%). 상대가 넘치게 막는 경우가 많아서, 마디를 열어 둔 채 기대하는 쪽이 손해였습니다. 그래서 상대의 실제 대응을 읽는 2수 읽기로 바꿨습니다.

**속도**
- 시뮬레이션 복사·채점 방식을 바꿔 보통 컴퓨터가 같은 수를 약 3.4배 빠르게 고릅니다 (평균 51ms → 15ms, 고르는 수는 588수 중 588수 동일).
- 어려움은 2수 읽기에 최대 1.2초까지만 씁니다(느린 기기에서는 그 안에 읽은 수 중에서 고름).
- 계산을 화면과 분리: 설치형은 웹 워커(다른 스레드), 아티팩트는 한 프레임에 약 10ms씩 나눠 계산. 완전판+Lv2에서 어려움 13차례 동안 화면 프레임 간격 최대 33ms (끊김 없음).
- 컴퓨터가 계산하는 동안 "컴퓨터가 생각하는 중…"을 보여 줍니다.

## 6-1. 화면 테마: 음악 마을 (리디자인)

'카르카손 같은 보드게임 느낌'을 원작 그림을 따라 하지 않고 독창적인 그림으로 냈습니다.

| 게임 요소 | 음악 마을 테마 | 카드 테마 |
|---|---|---|
| 타일 | 두께가 보이는 풀밭 판 (풀포기·꽃·나무 장식은 타일마다 고정) | 음표 색 카드 |
| 리듬선 | 흙길 | 흰 띠 |
| 박자 이름표 | 음표 색 나무 팻말 (박자 숫자를 끄면 작은 색 깃발만) | 흰 이름표 |
| 마디줄 | 나무 차단목 | 검은 막대 |
| 시작 타일 · 박자표 | 차단목 + 숫자, 시작 타일엔 깃발 | 막대 + 숫자 |
| 지휘대 | 보라 지붕 음악 정자 | 보면대 그림 |
| 지휘자 | 그림자가 있는 칠한 나무 말 | 납작한 말 |
| 보드 · 손패 · 창 | 나무 테이블과 나무 액자, 나무 쟁반 손패, 종이 패널, 숲색 버튼 | 라일락 펠트, 흰 패널, 남색 버튼 |
| 어두운 화면 | 어두운 호두나무 테이블, 갈색 종이 | 어두운 보라 |

- 설정 화면의 '학습 · 규칙 옵션'과 게임 메뉴에서 '화면 그림'으로 바꿉니다. 고른 테마는 기기에 저장됩니다.
- 앱 아이콘과 테마 색(설치형)도 음악 마을 그림으로 바꿨습니다.
- 음악 마을 타일은 장식이 많아, 보드에서는 같은 그림을 한 번만 그리고 재사용합니다 (타일 70장 보드: 그리기 요소 3,235개 → 210개).

## 7. Lv2 박자표 규칙

설계서의 "한 마디의 목표는 그 줄에서 가장 가까운 위쪽 박자표를 따름"과 카드 데이터의 "이 타일 이후 마디의 목표를 3박으로 바꿈"을 2차원 보드에서 판정할 수 있게 정했습니다.

1. 박자표 타일(3/4, 2/4)은 가운데가 마디줄이고, **한쪽에만 숫자**가 있습니다. 타일을 돌려 숫자가 향할 쪽을 정합니다.
2. **숫자가 적힌 쪽 마디부터** 그 박자가 되고, 마디줄 막대를 건너 **다음 박자표가 나올 때까지** 이어집니다. 실제 악보에서 박자표가 다음 박자표까지 유지되는 것과 같습니다.
3. 숫자가 없는 쪽(박자표의 뒤)이나 박자표가 없는 줄은 시작 타일의 4/4를 따릅니다.
4. 서로 다른 박자표가 **같은 거리에서 한 마디를 마주 보면** 둘 중 하나만 맞아도 완성으로 인정합니다(드문 경우).

예: 시작(4/4) ‖ 4분 · [3/4 박자표, 숫자가 오른쪽] · 2분 · 4분 → 박자표 왼쪽 마디는 목표 4박, 오른쪽 마디는 목표 3박. (학습 퍼즐 5장 7번 문제가 바로 이 경우)

## 8. 시뮬레이션으로 찾은 규칙 문제: 덜 찬 마디 닫기

컴퓨터끼리 2인 MVP 게임을 30판씩 돌려 비교했습니다.

| | 판당 맞은 마디 | 판당 틀린 마디 | 두 사람 점수 합(판당) |
|---|---|---|---|
| 설계서 원안 (덜 찬 마디도 닫기 가능) | 6.7 | 12.5 — 97%가 4박 미만에서 닫힌 마디 | 30.5점 |
| 덜 찬 마디 닫기 금지 | 8.2 | 5.3 — 전부 넘친 마디(막기) | 44.5점 |

마디줄은 누구나 거의 공짜로 꽂을 수 있어서, 상대가 찜한 마디를 1~2박에서 바로 닫아 0점으로 만드는 것이 가장 쉬운 최선수가 됩니다. 실물 게임에서도 똑같이 생기는 문제입니다. "목표 박이 안 된 마디는 닫을 수 없다(넘친 마디로 막기는 가능)"를 옵션으로 넣고 기본으로 켰습니다.

## 9. 첫 판 튜토리얼

설계서 13장 샘플 플레이를 그대로 따라 하며 배웁니다. 단계마다 허용된 행동 하나만 받습니다.

1. 시작 타일·마디줄 소개 → 2. 4분음표를 시작 타일 오른쪽에 → 3. 놓기 → 4. 지휘자로 찜 → 5. 차례 끝 → 6. 컴퓨터가 2분음표 → 7. "4박까지 몇 박 더?" 질문(틀리면 힌트) → 8. 4분음표로 1박 채우기 → 9. 놓기 → 10. 오른쪽 끝에 마디줄 → 11. 차례 끝 → 검산 퀴즈 → 완료 화면(6점, 틀린 마디·손패·지휘대·곡선 안내) → "컴퓨터(쉬움)와 한 판" 또는 "학습 퍼즐"

## 10. 설치형(오프라인) 버전과 올리는 방법

아티팩트 페이지는 서비스워커가 막혀 있어 설치·오프라인이 안 됩니다. 그래서 `npm run build:web`으로 만든 설치형 폴더를 따로 올립니다. 학습 퍼즐과 컴퓨터(워커)도 오프라인에서 그대로 동작합니다.

**GitHub Pages 자동 배포 (기본)**
- 주소: https://kimyounggaur.github.io/Music_Rudiment_Carcassonne/
- 저장소 `main`에 `webapp/`이 바뀌어 올라오면 GitHub Actions(`.github/workflows/pages.yml`)가 자동 테스트 → `build:web` → `gh-pages` 브랜치로 올리고, GitHub Pages가 그 브랜치를 공개합니다
- 테스트가 하나라도 실패하면 배포하지 않으므로, 깨진 버전이 학생 기기로 가지 않습니다
- 손으로 다시 올릴 일이 없습니다. 반영까지 2~3분. 진행은 저장소의 Actions 탭에서 보고, 코드 변경 없이 다시 배포하려면 같은 곳에서 'Run workflow'
- Pages 출처는 `gh-pages` 브랜치 (Settings → Pages). 첫 배포 때 켜 두었으므로 따로 할 일 없음

**태블릿에 설치**
- 안드로이드·크롬북·PC 크롬: 처음 화면의 ‘앱으로 설치’ 버튼 (또는 주소창의 설치 아이콘)
- 아이패드·아이폰: Safari 공유 버튼 → ‘홈 화면에 추가’
- 한 번 연 뒤에는 와이파이 없이도 열림. 새 버전은 다음에 인터넷이 될 때 자동으로 받음

**다른 곳에 올리기**: `webapp/dist-web/` 폴더는 Netlify Drop(app.netlify.com/drop에 폴더를 끌어다 놓기, 처음엔 임시 비밀번호로 보호되고 무료 가입해 claim하면 공개)·Vercel 같은 정적 호스팅에도 그대로 올릴 수 있습니다 (하위 경로에서도 동작, https 필요).
